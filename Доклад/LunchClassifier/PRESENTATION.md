# «Классификатор обеда» — Create ML за 2 минуты

**Доклад: 5–7 мин + вопросы**

---

## 1. О чём доклад

- **Задача:** обучить модель в Create ML на 3 класса (pizza / sushi / burger) и встроить её в iOS-приложение.
- **Демо:** пользователь делает фото еды → приложение определяет блюдо и показывает калории (из модели CalorieClassifier или по типу блюда).
- **Код:** загрузка `.mlmodel`, классификация через Vision + Core ML.

---

## 2. Create ML — что это

- Встроенный в экосистему Apple инструмент для обучения моделей **без написания Python**.
- Поддерживает, в том числе: **Image Classification** — классификация изображений по меткам.
- Модель экспортируется в формате **Core ML** (`.mlmodel`) и сразу подходит для iOS/macOS.

---

## 3. Подготовка данных (1 минута)

- Одна папка с **тремя подпапками** — по имени класса:
  - `pizza/` — фото пиццы  
  - `sushi/` — фото суши  
  - `burger/` — фото бургеров  
- В каждую — от 10–20 фото (чем больше и разнообразнее — тем лучше).
- Разрешение желательно не меньше ~299×299.

## 3b. Итоговый датасет: train / validation / test — зачем и что у нас

**Что в итоге собрали**

- **FoodClassifier (тип блюда):** две папки — **TrainingData** (pizza, sushi, burger; тысячи фото) и **ValidationData** (те же три класса; сотни фото). Собрано из Kaggle-архивов + Food-101, отфильтровано только под pizza/sushi/burger.
- **CalorieClassifier (калории):** одна папка **CalorieClassificationData** с подпапками cal_100, cal_200, … (фото с разметкой по диапазону калорий). Create ML сам делает из неё split на train/validation при обучении.

**Зачем нужны train, validation и test**

| Разбиение | Зачем нужно | У нас в проекте |
|-----------|-------------|------------------|
| **Training (обучение)** | На этих данных модель подстраивает веса. Без них обучение невозможно. | Есть: TrainingData для еды, для калорий — часть CalorieClassificationData (auto). |
| **Validation (валидация)** | Данные, на которых **не** учимся, но смотрим метрики во время обучения (переобучение, ранняя остановка). Должны быть отдельно от train. | Есть: ValidationData для еды; для калорий Create ML сам откладывает часть (Auto Split). |
| **Test (тест)** | Финальная проверка «в боевых условиях» — один раз после обучения, чтобы оценить качество без подгонки. В Create ML не обязателен. | Отдельного test-набора нет: для демо достаточно train + validation; финальная проверка — в приложении на своих фото. |

**Что можно убрать в нашем случае**

- **Отдельный test** — не делали. Create ML не требует отдельной папки «Test»; validation уже даёт честную оценку. Итоговое качество смотрится по метрикам на validation и по поведению в приложении.
- **Для калорий** мы не выносили validation в отдельную папку — дали одну папку и выбрали в Create ML **Validation: Auto Split from Training Data**. Этого достаточно.

**Итого:** train обязателен; validation — чтобы не переобучиться и смотреть метрики; отдельный test для этого доклада можно не делать.

## 4. Обучение в Create ML (1–2 минуты)

1. Открыть **Create ML** (или через Xcode: File → New → File → Image Classification).
2. Указать папку с данными как **Training Data**.
3. **Validation** оставить **Automatic** (или указать папку ValidationData).
4. Нажать **Train** и дождаться окончания.
5. Сохранить модель как **FoodClassifier.mlmodel**.

Главное — показать процесс обучения в GUI (выбор данных, кнопка Train, метрики, экспорт).

## 4a. Параметры обучения: итерации и аугментации — что ставить и зачем

**Что такое итерации (Maximum Iterations)**

- **Итерация** в Create ML — это один цикл обновления модели по обучающим данным. Условно: модель «прошла» по данным и подправила свои **веса** (числа внутри сети, которыми она отличает классы). Больше итераций — модель дольше учится и обычно точнее, но дольше по времени и есть риск переобучения.
- Create ML может **остановиться раньше** максимума, если модель **сошлась** (converged): метрики на validation перестали улучшаться, дальше учить смысла нет.
- **Что ставить:** для **FoodClassifier** (3 класса) обычно хватает **25–50** итераций (дефолт 25 — нормально). Для **CalorieClassifier** (много классов cal_100, cal_200, …) лучше **50–100**, чтобы модель успела выучить все диапазоны. Отдельный test не нужен — смотрим по validation.

**Что такое аугментации (Augmentation)**

- Это **искусственное разнообразие** данных: к каждому фото применяются случайные преобразования (отражение, поворот, кадрирование, яркость). Модель видит не только исходные картинки, а ещё их вариации — так она лучше обобщает и меньше переобучается на «запомненные» кадры.
- **Что включать в нашем случае:**

| Параметр | Зачем | Рекомендация |
|----------|--------|---------------|
| **Flip** (отражение) | Фото еды не имеют «лево/право» — отражение не меняет класс. | **Включить.** |
| **Rotate** (поворот) | Тарелка может быть снята под углом — модель учится узнавать блюдо в любом повороте. | **Включить.** |
| **Crop** (кадрирование) | Часть кадра — та же еда. Улучшает устойчивость к композиции. | По желанию. |
| **Expose** (яркость/экспозиция) | Разное освещение в жизни и в датасете. | По желанию. |
| **Blur / Noise** | Шум и размытие. Для нашего датасета не обязательны. | Можно не включать. |

**Итого что ставить**

- **FoodClassifier:** Iterations **25–50**, аугментации **Flip + Rotate** (при желании Crop, Expose).
- **CalorieClassifier:** Iterations **50–100**, те же аугментации **Flip + Rotate** (при желании Crop, Expose).
- Отдельную «тестовую» выборку в Create ML можно не указывать — достаточно train + validation.

## 4b. Что мы видим после обучения: график и метрики

После нажатия **Train** Create ML показывает вкладку **Training** с графиком и логом. Вот что это значит.

**Что за график**

- По оси **X** — **Iterations** (итерации): шаги обучения.
- По оси **Y** — **Accuracy** (точность), в процентах: доля примеров, которые модель угадала правильно.
- **Две линии:**
  - **Training Accuracy** (тёмная, квадратные маркеры) — как модель отвечает на **обучающей** выборке (на этих данных она подстраивала веса).
  - **Validation Accuracy** (светлая, круглые маркеры) — как модель отвечает на **валидационной** выборке (этих данных она во время обучения не видела).

**Что по нему можно понять**

- **Рост обеих линий** — модель учится: и на train, и на validation точность растёт.
- **Линии выходят на плато** (почти горизонталь) — модель **сошлась** (converged): дальше учить почти нечему, метрики стабилизировались.
- **Training и Validation близки** (например, 98–99% train и 95% validation) — переобучения почти нет, модель неплохо обобщает на новые фото.
- **Training сильно выше Validation** (например, 99% vs 70%) — возможное переобучение: модель «запомнила» train и хуже работает на новых данных.

**Надписи справа и внизу**

- **99% Training, 95% Validation** — лучшие достигнутые точности на train и validation за всё обучение.
- **Testing —** в нашем сценарии не заполняется (отдельный test не задавали).
- **«Model converged at 14 iterations»** — обучение остановилось на 14-й итерации, хотя максимум мог быть больше (например, 50): Create ML сам остановил тренировку, когда метрики на validation перестали улучшаться (ранняя остановка). Это нормально и экономит время.

**Итого:** график — это **кривые обучения**. По ним видно, что модель выучилась (высокая точность), сошлась (линии вышли на плато) и не переобучилась (train и validation близки). После этого можно сохранять модель и подключать в Xcode.

## 6a. Шаг: Создаём шаблон приложения под модель (слайд)

**Как устроен UI и логика — кратко, без деталей**

- **Экран:** один поток: сверху — область под превью фото (пустое место или выбранное изображение), под ней — кнопка выбора фото и сброс, ниже — блок результата (загрузка / ошибка / класс + калории). Всё в одном скролле, без лишних экранов.
- **Поток данных:** пользователь выбирает фото из галереи → приложение подгружает картинку и передаёт её в «движок» классификации → движок возвращает метку и (если есть) калории → UI обновляет блок результата. Модель в коде не вызывается из UI напрямую: есть один слой (классификатор), который принимает изображение и отдаёт результат — так потом просто подключаем обученную модель.
- **Состояния экрана:** пока нет фото — показываем плейсхолдер и призыв выбрать фото; после выбора — превью и индикатор «определяю…»; по готовности — либо класс + уверенность + калории, либо сообщение «не уверены» / ошибка. Сброс очищает фото и результат.
- **Размеры фото (сжатие, разные разрешения):** фото из галереи бывают разных размеров и пропорций. В UI превью показываем в **фиксированном квадрате** (например 280×280 pt), картинку подгоняем по размеру без искажений (заполнение кадра + обрезка лишнего), чтобы верстка не «поехала». В модель картинку не ресайзим вручную: **Vision** при запросе к Core ML сам приводит вход к нужному размеру (**centerCrop** — центральная часть, масштаб под вход модели). Так и огромные, и маленькие фото обрабатываются одинаково.
- **Бизнес-логика по ответу модели:** модель возвращает метку класса и уверенность (confidence). Результат считаем «нашим», только если **уверенность выше порога** (например 80%) **и** метка — один из ожидаемых классов (pizza, sushi, burger). Если да — показываем класс, процент уверенности и калории (если есть модель калорий). Если **нет** (низкая уверенность или другой класс) — честно пишем: «Не уверены, что это пицца, суши или бургер», калории не показываем. Так не вводим пользователя в заблуждение.
- **Зачем так:** шаблон уже готов под подстановку модели: поменять нужно только загрузку `.mlmodel` и вызов классификации. Интерфейс от этого не зависит — только от того, что вернул классификатор (метка, уверенность, калории или пусто).

## 7. Код: загрузка модели и классификация

## 7b. Трудности определения калорий по фото и как их решить (слайд после «чего-то не хватает — калорий»)

**Почему калории сложнее, чем классификация типа еды**

- **Тип блюда** — задача **классификации**: конечный набор классов (pizza, sushi, burger), картинка → один из них. Модель учится узнавать визуальные признаки категории.
- **Калории** — по сути **регрессия** (число от 0 до тысяч), но в Create ML удобнее сводить к **классификации по диапазонам** (cal_200, cal_500 и т.д.): одна картинка → один «бакет». Сложность в том, что одно и то же блюдо на фото может быть разного размера порции, под разным углом, с разной калорийностью — один визуальный класс, много возможных значений калорий.
- **Типичные трудности:**
  - **Размер порции:** на фото не видно масштаба (тарелка большая или маленькая, сколько грамм). Решение: учить на данных, где калории привязаны к порции/блюду; допускать погрешность (например ±100–200 ккал) или выдавать диапазон.
  - **Состав и способ приготовления:** одна и та же «пицца» — разная калорийность (толстое тесто, двойной сыр и т.д.). Решение: больше разнообразных данных с разметкой калорий; классы-диапазоны (cal_300, cal_500) вместо точного числа.
  - **Мало размеченных данных:** датасетов с фото + калориями меньше, чем с просто меткой «пицца/суши/бургер». Решение: объединять датасеты (Nutrition5k, Food_Calorie_Dataset и др.), балансировать классы (undersample/oversample), аугментации.
  - **Дисбаланс классов:** в реальных данных много «средних» калорий (200–400), мало экстремумов (100, 1000+). Модель перекашивается в сторону частых классов. Решение: балансировка при сборке датасета (ограничить число примеров в больших классах, добить маленькие копиями или доп. данными).
- **Итог:** калории по фото — задача сложнее и неоднозначнее, чем «что за блюдо»; мы упрощаем её до классификации по диапазонам и явно допускаем погрешность, а пользователю показываем диапазон или округлённое значение.

### Слайд 14: Обучение CalorieClassifier в Create ML

**Заголовок:** Обучение модели калорий в Create ML

**Показывать:**
- **Training Data:** папка `CalorieClassificationData` (внутри — подпапки по классам калорий).
- **Validation:** Auto Split from Training Data.
- **Параметры:** итерации 50–100 (классов много), аугментации Flip, Rotate (по желанию Crop, Expose).
- Train → смотрим графики accuracy по итерациям → экспорт через Output → Get → сохраняем **CalorieClassifier.mlmodel**.

### Слайд 15: Интеграция CalorieClassifier в приложение

**Заголовок:** Подключаем модель калорий в проект

**Показывать:**
- Перетаскиваем **CalorieClassifier.mlmodel** в группу с исходниками в Xcode (target LunchClassifier).
- В коде: отдельный слой (например `CalorieRegressor` / `CaloriePredictor`) загружает эту модель через Vision так же, как FoodClassifier — `VNCoreMLModel`, `VNCoreMLRequest`, `imageCropAndScaleOption = .centerCrop`. На выходе — метка класса (например `cal_500`) → парсим число (500) и отдаём в UI.
- Калории вызываем **после** классификации типа блюда: если пользователь видит «pizza / sushi / burger» и уверенность ≥ 80%, показываем ещё и калории из CalorieClassifier; если «не уверены» — калории не показываем.
